# FluxCreate open-source release specification

Prepared 1 November 2026. Planning only; no license, visibility, repository settings or payments changed.

## Objective
Make FluxCreate a credible, maintainable open-source creative suite that another person can legally obtain, install, understand, use for a documented workflow, and contribute to without private assistance or mandatory paid AI.

Success means reliable supported behavior and honest limits, not complete parity with eight established professional products.

## Scope
Prepare legal/provenance records, repository controls, repeatable onboarding, documented app workflows, integration contracts, security/privacy review, contributor governance, release artifacts, launch materials and a sustainable operating model.
Separate public source release from public hosted service and paid generation. Full professional feature parity, collaboration infrastructure and managed billing do not block a correctly scoped source alpha.

## Global requirements
- Node.js 24.x and pnpm 12.3.4 remain the current reproducible baseline until a separately verified update.
- Preserve native project IDs and internal compatibility directory names.
- Core editing and supported exports work without provider keys.
- No live provider calls or private credentials in ordinary CI.
- Personal provider billing never silently falls back to shared managed billing.
- License selection remains an owner decision; recommendations are not adopted licenses.
- Current credentials, private media and runtime state must not enter published source, releases, screenshots or examples.
- No model or imported document may grant itself permission to spend, publish, access arbitrary local files or execute code.
- Keep the deployed workspace protected until a separately qualified public-service launch.
- Preserve the confirmed 50% contribution-margin target for future managed creation services; do not confuse it with net company profit.
- Only publicize feature and compatibility claims backed by release evidence.
- Plan work now; execute visibility changes, licensing and announcements only after explicit owner decisions.

## Alpha acceptance
A release commit has an adopted compatible license, redistributable dependencies/assets, no unresolved confirmed credential disclosure, passing fresh-install CI, recoverable supported project flows, a private security-reporting route, a named maintainer, release notes and a usable contribution path.
Three flagship workflows are qualified; every included app has a smoke/recovery check and accurate maturity label.
Public hosting and paid features have independent ownership, isolation, recovery and cost gates.
