# Photo Curves implementation plan

Scope: bounded source-preserving per-photo RGB + red/green/blue Curves. No adjustment-layer architecture. Keep native version 1 and absent Curves absent for old projects. Optional curves object contains enabled, points and channels. Two to sixteen ordered integer input/output pairs per curve, input endpoints fixed at 0/255; endpoint outputs editable. Strictly increasing input; bounded outputs may rise or fall. Piecewise linear interpolation deliberately avoids spline overshoot, with rounding per stage. Levels runs first, then composite Curves, then channel Curves, mask, appearance/compositing. Identity curves bypass rasterization.

Inspector: visible SVG graph, numeric accessible point fields, channel switch, bounded insertion/removal (endpoints retained), current/all reset and enabled bypass. Drafts do not preview artwork. Explicit Apply commits every channel together as one undo; selection/document changes discard drafts; locks/recovery/import disable controls. Original source bytes and alpha stay unchanged.

Verification: write failing native/model and actual browser pixel tests first. Cover malformed/oversized/reordered data, 256 identity values, Levels ordering, independent channels, alpha, source preservation, one undo/redo, stale drafts, locks, resets/bypass, source replacement, native save/reload, PNG/portable/independently decoded PSD and studio source. Run existing channel Levels/source/PSD/editor regressions, all unit tests and build. Document local evidence and limitations; root owns release/integration and commits.
