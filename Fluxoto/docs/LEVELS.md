# Photo Levels and source histogram

Implemented and locally verified in the second parallel continuation. Deployment status is tracked in the suite release record.

Select one photo layer and expand Photo Levels. Its RGB histogram samples the decoded original image at up to 512 pixels per side, before Levels, other adjustments or masks. Counts are alpha-weighted; fully transparent pixels are excluded. It is not a full-resolution document histogram or managed-color measurement.

Black and white input points are 0–255 with black strictly below white; gamma is 0.1–10. The same RGB lookup is applied to each channel, with alpha unchanged. Draft numeric edits do not alter artwork until Apply Levels; the complete application forms one undo step. Reset values prepares neutral values, and Apply commits them. Enable Levels bypasses the operation without erasing saved parameters. Locked/recovery/importing states disable edits. Committed document changes replace stale draft controls. The histogram stays mounted through unrelated edits to avoid decoding the photo repeatedly.

Native files preserve source bytes and editable Levels. Rendering applies Levels before the mask, followed by existing appearance filters/compositing. PNG/JPEG and separate PSD pixel layers use the rendered result. Portable motion/Exchange rasterizes adjusted layers once and clears baked controls; native originals retain the controls. Direct model conversion emits an explicit warning if callers omit portable rendering. The same renderer supplies embedded studio snapshots. Temporary surfaces remain bounded to the existing 8192-side / 32 MP limits and are released after drawing.

Verification: five new unit groups (39 Fluxfoto total including photo-source checks), nine actual-browser groups covering exact RGB, transparency/mask, one-step undo/redo, invalid range, disable/reset, native source identity, portable exactly-once baking, autosave/reload, stale drafts and locks. Actual layered PSD bytes are decoded independently. Existing 11 PSD and eight selection/batch-edit groups pass. The shared studio-object renderer also preserves adjusted pixels and recoverable native controls. The existing reviewed AI planner can propose bounded Levels edits; validation retains source bytes and enforces locks, selection scope and atomic failure. Six official MCP/editor integration checks pass. Independent review found no actionable source/alpha/portable/draft issue. No paid model calls.

Still missing: separate adjustment layers, per-channel/output Levels, Curves, live preview before Apply, presets, color-managed/high-bit-depth processing, full-document histogram, pixel readout/clipping warnings and large-photo performance profiling. Levels currently runs on the bounded main-thread raster surface; this is not a claim that the 32 MP performance backlog is solved.

Neutral Levels bypasses extra rasterization. Fresh PNG exports of a fractional-size, rotated photo are byte-identical before and after neutral Apply, and portable output retains the exact original source. The regression uses fresh export canvases: repeated reads of Chromium’s interactive canvas can switch its rendering backend and alter antialiased edges even when drawing the same unchanged document. Independent reproduction confirmed this readback artifact without Levels.
