# Selection-clipped photo paint and erase

Implemented and verified locally on 2026-10-15. Suite deployment is recorded separately.

Choose Selection or Lasso, create or combine areas, then choose Brush/Eraser with Selected photo as its target. Rectangle, ellipse, freehand lasso, add/subtract/intersect, inversion and feather constrain the photo stroke. The active tool hint identifies selection clipping. Painting still requires one visible, unlocked image with a linked decoded source and starts inside its frame. Separate-stroke mode and mask painting keep their existing behavior.

Each stroke captures an immutable selection and feather value at pointerdown. Deselecting or changing the selection afterward does not change committed paint. The native clip stores original document dimensions, bounded selection geometry, feather in original document pixels, and an affine mapping into the retained photo paint basis. Feather is rasterized in original document pixels before mapping; this avoids approximating nonuniform scales with a single feather radius. Rotation and later nonuniform resize carry paint and its clip together. Outside the original document rectangle always stays unselected, including for inverted selections. Replacement/relink retains the existing paint and clip just as it retains other local edits. The original image bytes remain untouched.

The isolated stroke raster is multiplied by its selection alpha, then composited with stroke opacity exactly once. Erase changes only the selected image's alpha. The existing order stays source → local clipped/unclipped paint and erase → Levels → Curves → layer mask → existing appearance/compositing. Native saving retains recipes; PNG/JPEG, portable exports, PSD raster layers/composite and studio snapshots use the same renderer. Portable baking clears paint after applying it once. PSD stores rendered pixels rather than editable clipping recipes. Absent/empty paint and existing unclipped strokes retain their prior paths.

Unfinished strokes remain separate from committed state. Save/export/autosave and AI see committed artwork. Selection geometry or feather changes during a stroke cancel the preview; stale pointer release cannot commit it. Existing Escape/blur/tool/target/mask/edit/import/undo and pointer ownership protections remain. One completed gesture is one undo; Clear photo paint is reversible.

## Bounds and allocation policy

Existing paint bounds remain 8192 pixels per side / 16 megapixels for the frame and retained basis; 256 strokes, 4096 points per stroke, and 16384 paint points per image. Each selection allows at most 32 operations and 5000 vertices per shape, with **32768 aggregate retained clip vertices per image** across all strokes. Native validation rejects malformed/unknown fields, invalid operations, nonfinite/coerced values, unsupported shapes, invalid/singular matrices and out-of-budget data before rendering. Exact negative zero in matrices is canonicalized to zero for native JSON/autosave equality; other affine values are not rounded. A gesture that exceeds a bound is canceled without changing previous artwork.

Captured document frames are limited to 8192 pixels per side / 16 megapixels. Feather is 0–100 original document pixels. Padded selection surfaces are limited to 24 megapixels each; selection rasterization uses two padded temporary canvases and a cropped document stencil. Only one cropped stencil of up to 16 megapixels is retained globally, dropping the old one before constructing its replacement. Clipped drawing reuses two scratch canvases per layer draw, each bounded by the existing renderer's 8192-side / 32-megapixel raster limits, then releases both. Existing source/render surfaces are additional allocations. Clip geometry is normalized again during gesture updates, and differing selections may rerasterize; these are bounds, not performance measurements. Large-photo CPU/peak-memory profiling, tiling and worker rendering remain open.
