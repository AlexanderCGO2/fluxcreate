# FluxLab studio

FluxLab opens with an empty creative workspace. Its decorative artwork is CSS; no example is presented as a generated result. Text, image, video, and speech results come from the live Flux AI Gateway through the generation service. The model picker uses the service's capability catalog, filtering independently for each supported medium. Model-default image dimensions avoid forcing unsupported sizes. Provider failures are shown without replacing the previous result.

The interface includes prompt starters, model selection, output size or text length, cancellation, result downloads, text copying, prompt reuse, light and dark appearance, and a responsive library. A result can be sent to Fluxfoto, FluxDesign, Fluximiére, or Fluxiffects through the shared validated handoff. The destination editor previews it before adding editable content to the current project.

Results are saved in IndexedDB (`fluxlab-library-v1`) on the current origin. A small metadata catalog supports library browsing and search without loading image bytes. Full results are read on demand. Result and metadata records are added in one transaction; duplicate identifiers never replace existing work. Storage failures keep the unsaved result visible and downloadable. Starting another creation or opening an old one requires saving or explicitly discarding that unsaved result. Removing a saved result requires confirmation. Download copies to retain work independently of browser storage.

Cancellation aborts the active request and rejects late responses. Closing the app aborts an in-flight request. Model availability does not block access to previously saved results. The frontend never stores API credentials: local generation uses a short-lived session token, while hosted requests use the suite API routes.

Verification: `node scripts/browser-smoke.mjs` uses an isolated browser and a deterministic injected service. It covers capability filtering, actual text and PNG downloads, clipboard, durable library recovery and search, cancellation propagation, service errors, duplicate IDs, explicit removal, the handoff handshake, offline library access, and dark/mobile layouts. Its screenshots and results are test fixtures under `artifacts/browser`, not claims of live model output.

## Video, voice, and recovery

FluxLab also offers Video and Speech modes using the live Gateway capability catalog. Video duration/aspect and speech voice/format choices come from the selected model. Automatic choices are omitted from requests. Accounts without speech models show an unavailable state instead of a fabricated model. WAV scripts are limited to 400 characters; supported MP3 models allow up to 1,500.

A video request is recorded before submission with its stable request identifier. The returned signed recovery ticket is saved in IndexedDB. Pause checking stops local polling and downloads; it does not claim to cancel provider work or charges. Reloaded jobs wait for an explicit Resume checking action. An uncertain submission retries its original identifier. Provider errors, interrupted downloads, and save failures retain the recovery record. MCP recovery links are captured without replacing other jobs, then removed from the address bar. Recovery still depends on the provider and ticket remaining available.

Completed videos are streamed through the same-origin media route with a 64 MiB cap, decoded, and stored as permanent Blob records. Expiring provider URLs are not saved as the library asset. Video metadata is bounded to 8,192 pixels per side, 32 megapixels, and 24 hours; WebM indefinite metadata is resolved by an end seek. Speech MP3/WAV data is decoded before Blob storage. The visible audio bars are decorative, not a measured waveform. Playback object URLs are revoked when results change. Both media types download as their original files and hand off to Fluximiére or Fluxiffects for import review.

The library upgrades in place from schema version 1 to 2, preserving earlier image/text results. Video result, catalog metadata, and completed-job removal commit together. Existing save/delete identity protections apply to all media. Reopening the same completed video link reuses its existing Blob without replacing it; a conflicting identifier preserves the original. Updates require the recovery job to remain present, so removing a job in another tab prevents stale responses from restoring it or automatically saving a late completion. `node scripts/media-browser-smoke.mjs` verifies real WebM/WAV playback, exact downloaded bytes, Blob recovery, old-library migration, pending jobs, failure/retry without a new request ID, same-tab MCP recovery, and the no-speech-model state. `node scripts/jobs-browser-smoke.mjs` checks delayed responses and atomic completion across two tabs. These generated media fixtures make no paid provider calls.

Speech generation is synchronous. A disconnected or cancelled audio request has no background recovery ticket; starting it again is a new provider request and can incur another charge. A successfully returned audio Blob remains protected by the normal unsaved-result and library recovery controls.
