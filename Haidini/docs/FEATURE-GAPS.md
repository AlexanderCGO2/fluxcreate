# FluxEffects: feature gaps and delivery plan

Audit date: **9 October 2026**. Reference product: **Houdini**. This report extends the existing [complete-toolset roadmap](FULL-TOOLSET-ROADMAP.md) with explicit status, gaps and acceptance criteria. It supersedes any reading of attractive templates as evidence of solver or production-feature parity.

The current official [Houdini 22 documentation index](https://www.sidefx.com/docs/houdini/) separates geometry, animation, characters, simulation, rendering, compositing and pipeline tools. FluxEffects has a functioning subset across graph-based motion design and bounded simulation; it does not implement the full Houdini operator ecosystem.

Evidence inspected: `src/engine/catalog.ts`, `project.ts`, `evaluator.ts`, `animation.ts`, simulation engines/controllers, viewport/material tools, graph/inspector/timeline UI, local project/history/memory services, hosted browser API, exchange bridge, export code and the existing verification scripts. Existing test evidence is documented in the README and roadmap; this audit did not rerun every solver/browser suite.

## Detailed delivery sequence

| Stage | Concrete work and prerequisites | Acceptance gate |
| --- | --- | --- |
| H0 — reliable existing workflows | Retained snapshot placement shipped in the earlier suite release; continue backup/storage/cancel feedback and asset deduplication before raising budgets. | Native save/reload and undo retain source; failed decode, stale imports and locked replacement are atomic; local and hosted paths agree; PNG/GLB exports contain actual pixels and never leak source JSON into AI. |
| H1 — shared geometry/field foundation | Introduce versioned indexed meshes, point/vertex/face attributes, groups, source/collider adapters and dependency-aware job/cache keys. | One mesh renders, emits and collides through explicit conversions; edits invalidate only dependent jobs; units and coordinate conventions survive interchange; invalid topology fails before GPU allocation. |
| H2 — useful modeling | Add selection and transform, then extrude/bevel/subdivision/boolean; import basic packaged glTF; expose reusable node groups. Start with a product pedestal/lettering task. | Upstream edits preserve documented selection rules; topology fixtures check manifoldness and normals; three-level groups reopen and export; every direct/AI edit uses the same undoable commands. |
| H3 — animation and assets | Add curve tangents, key multi-selection, clips, constraints, source relink and glTF motion export after hierarchy rules exist. | An animated source can be reopened, retimed and exported at reference timestamps; motion survives independent loader comparison; locked tracks and stale previews remain protected. |
| H4 — physical fluid prototypes | Prototype a bounded 3D liquid tank and pressure-projected smoke volume outside the preset library. Choose CPU/WASM/WebGPU backend from measured accuracy and device support. | Liquid mass drift and penetration stay within published tolerances; pouring fills/settles; smoke projection lowers divergence; deterministic/replay tolerances are measured; cached backward seeks reproduce frames. |
| H5 — solver products | Build ordinary controls, cache management and source/collider tools around proven prototypes; then rigid contacts/fracture, cloth self-contact, strands and one material model at a time. | Resting stack remains at rest, fracture responds to thresholds, cloth self-contact reduces penetration, granular slope tests are repeatable; bounded jobs can pause/cancel without corrupting caches. |
| H6 — production appearance/output | Texture/UV workflow, shader graph, controlled color pipeline, offline render adapter, image sequences and render queue. Share image/compositor infrastructure with other studios. | Known texture/material scenes roundtrip; color patches are consistent; output timing and decoded frames match expected state; missing dependencies and resumed render jobs are explicit. |
| H7 — characters/environments | Rig/skin/retargeting foundations first; then groom, terrain erosion, crowds and tissue in separate milestones. | Real rig fixture retargets and scrubs; saved guides reconstruct groom; erosion tracks material; agents use valid animation transitions; each feature has its own tested example and limitations. |
| H8 — production integration | Evaluate USD/Alembic/OpenVDB adapters, headless cooking, farm/task service and custom operator API. Define licensing/runtime/deployment constraints before integration. | Interoperability checked with independent tools; recoverable task states and idempotent publishing; untrusted scripts/assets cannot bypass budgets or read arbitrary local files. |

H1 is the dependency gate for H2/H4/H5, while H0 can ship independently. H3 requires stable hierarchy; H6 requires stable geometry/material assets. H7/H8 are separate long-term programs, not hidden tasks inside “finish the clone.” Detailed dates need prototypes, benchmark hardware and reviewed scope first.

## Verification and implementation freeze

### Direct graph selection increment — 12 October 2026

The [direct selection plan](GRAPH-DIRECT-SELECTION.md) adds **Box select** and Shift-drag on empty canvas, Ctrl/Command/Shift-click membership, and direct movement of selected nodes or their selection rectangle. Numeric organization remains available. Selection is temporary; pointer release commits one validated relative move, preserving group offsets and protected parameter values. No-op gestures create no revision; invalid coordinates and selections exceeding 32 commands are rejected atomically.

Escape, pointer cancellation, window blur and project identity/revision/selection/disabled changes restore committed positions. Cancelled native callbacks cannot restart a draft or commit after pointer release, and cancellation retains the current graph viewport. Native arrow-key layout movement is disabled; keyboard layout editing uses the existing numeric organizer. Save/export never read canvas drafts.

Evidence: three new transaction tests pass; the direct browser suite passes ten groups including selection, both marquee entry paths, click modifiers, native group dragging, cancellation, undo/redo, native download/reload and byte-identical before/after PNG output. A separate actual NodeGraph browser harness passes five groups covering native selected-node commits and disabled/identity/revision/focused-node invalidation. Existing graph batch (5), graph editor (4), graph authoring (4) and design consistency (4) browser groups pass. App and developer-fixture TypeScript checks and staging build pass. The complete Node suite passes **112/112** with sibling dependency access. An initial sandboxed run blocked the motion-editor provider fixture; the isolated fixture and complete elevated rerun pass. Cancellation also preserves the original docked viewport when leaving full screen.

### Graph organization increment — 9 October 2026

**Organize** adds a temporary selection through Ctrl/⌘-click or a named checkbox list, plus **Select upstream branch**. The inspector and AI scope still use the focused node. Selection and numeric drafts do not change the project or revision. Move selected layouts by a numeric X/Y offset, align left, arrange a row, duplicate, or delete in one ordinary atomic patch and one undo. At this baseline, multi-node dragging was unavailable; the 12 October increment above adds direct movement while retaining these numeric controls. Layout positions persist; the temporary organization selection does not.

Duplication retains parameters, animation, visibility and exact retained source/preview bytes. Internal wires reconnect to the copied nodes; external inputs stay shared and external outputs are not connected automatically. Copies therefore leave the rendered scene unchanged until explicitly connected. Scene output and nodes with protected parameters cannot be duplicated or deleted through the batch controls. Existing validation enforces graph, rendering, coordinate and animation budgets. Operations exceeding **32 commands** fail before any mutation; a large selection is never silently split into separate edits. This remains ordinary graph organization, with no encapsulated groups, custom operators or exposed subgraph controls.

Fresh evidence: **109 Node tests**, TypeScript and staging build pass. `scripts/graph-batch-smoke.mjs` passes **5 actual-browser groups** covering Ctrl-click/list selection with exact project equality, relative layout and single-step undo/redo, animated branch copies and remapped wires, atomic deletion and output protection, upstream selection, both themes, nested Escape, native reload, and rejected 37-command duplication with the complete revision unchanged. Seven dedicated unit tests also compare copied branch evaluation, exact source bytes and immutable originals. Existing graph-authoring, graph-editor and design-consistency checks each pass **4 browser groups**. Screenshots and results are in `artifacts/studio/graph-organize-*.png` and `graph-batch-smoke.json`. No provider calls were made.

### Graph authoring increment — 9 October 2026

**Find nodes** searches the current graph by label, operator, category, ID and editable parameter values; terms combine as an AND search. Retained source documents and preview bytes are excluded. Choosing a result focuses that node and its inspector without changing the project revision. Ctrl/⌘+F works inside the graph; Escape closes search before leaving full screen.

**Issues only** shows missing required inputs, evaluator/renderer messages and branches that do not reach Scene output. Missing inputs offer only source nodes that pass the existing type, cycle, duplicate, input-multiplicity and output-budget validation. An unused renderable branch can explicitly connect to Scene output. Each repair uses the ordinary atomic command/revision/history path; no automatic repair runs. Existing locks protect parameter values (unchanged by a connection), while topology remains editable under the same policy as manually drawn wires. Repair controls are disabled during a blocked preview. This earlier increment did not include graph profiling, multi-node authoring or reusable subgraphs; bounded multi-node organization is recorded above.

Fresh evidence: **102 Node tests**, TypeScript check and staging build pass; the new `scripts/graph-authoring-smoke.mjs` passes **4 browser groups**, existing graph-editor coverage passes **4 groups**, and design-consistency coverage passes **4 groups**. The new workflow checks value search and focus with project deep-equality, inspector reopening with the result still centered, valid repair candidates, missing/unused diagnostics clearing, single-step undo/redo, keyboard focus and nested Escape, reopened wires, and light/dark layouts. `artifacts/studio/graph-authoring-smoke.json` and `graph-search-*.png` record the results. No provider calls were made.

### Earlier source-foundation audit (historical)

The initial planning audit removed unfinished cross-app controls while the shared renderer was being completed. Its source foundation passed three Node tests and a 32-test targeted regression subset. The subsequent suite release completed source controls and floating-helper integration; the historical foundation-only results are not the current feature status. This graph-authoring increment does not rerun every prior source-object or AI browser workflow.

Every future milestone must include source migration, failure recovery, undo/locks, keyboard handling, export verification and measured performance. Existing protective budgets remain in force until evidence justifies a change; a larger configured limit alone is not an optimization.

### Developer fixtures and retained simulation issue — 12 October 2026

Application and developer-fixture TypeScript checks now run separately in the release matrix. Paint/GPU browser fixtures and the graph cancellation harness are strictly typed. The GPU particle fixture passes seven groups, and the liquid invariant checks pass. No production solver behavior changed.

At this baseline the paint rewind check intermittently exceeded its unchanged 0.001 pigment tolerance: an unchanged baseline run measured about 0.00204, and the typed fixture about 0.00210. The 13 October [checkpoint-seek correction](PAINT-CHECKPOINT-SEEK.md) now reuses retained frames in both directions and passes that original check, plus palette/liquid/eviction regressions. Cached exact-frame restoration is verified; bit-identical recomputation after arbitrary eviction or across GPU drivers remains an open reliability target.
