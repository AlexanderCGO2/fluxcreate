# Rolling trim

Implemented scope: select the left of two exactly adjacent video clips or two audio clips on one track. Move only their shared cut; keep the left start, right end, sequence duration and every other track fixed. The left duration gains delta, right start gains delta, right duration loses delta, and right source-in gains delta times its own positive playback speed. Each surviving source sample keeps its original timeline placement. No linked A/V or silent ripple.

Reject the whole edit for missing/locked clips, gaps, ambiguous adjacency or any same-track overlap across the pair, fades/transitions, unavailable media or unknown duration, invalid existing source ranges, insufficient source handles or less than max(one sequence frame, 0.01 seconds) remaining on either side. Actual media durations override retained metadata in the UI. Numeric cut seconds snap to the sequence frame grid; frame nudges move by 1 / actual fps, retaining an imported off-grid cut's phase.

Interaction: inspector numeric cut and frame controls, plus a pointer slider preview. Pointer release applies one history entry; Escape, window blur, pointer cancellation, a document/selection/context change discard the preview. A foreign pointer cannot finish it. Preview is separate from committed autosave/native/movie export data. Keyboard slider changes and numeric/frame actions are atomic single edits. No-op edits create no history.

Validation plan: RED unit contract before implementation; model/source-sample, mixed speed, fractional rate, minimum duration, source bounds, lock/overlap/fade rejection, immutable input and native roundtrip. Browser exercises real controls and gesture, cancellation, one-step Undo/Redo, source metadata measurement, reload/native save. Generated multicolor media and stereo cues are exported and independently decoded to check the moved cut and fixed source placement. Run the full app unit suite, build and existing browser/editor/slip/ripple/audio export regressions. Implementation and measured results will be recorded below only after checks run.

## Measured verification — 2026-10-13

The planned implementation is complete for the bounded scope above. Select the left clip and use **Rolling trim** in Clip properties. Keyboard users can enter the shared cut time, activate the one-frame buttons, or focus the preview slider and use arrow keys. Slider dragging previews the actual program monitor and both timeline rectangles without modifying saved data. Opening Export discards a pending roll; the native export reads the committed cut. Both media durations are measured from embedded sources. All fades are conservatively rejected; this release does not reconstruct transition envelopes or add linked picture/sound. Bounded [slide editing](SLIDE-EDITING.md) is available as a separate command.

RED evidence: the initial four model contracts failed because the rolling command/bounds were absent; the browser test failed because the Rolling cut time control was absent. An additional exact 100 fps minimum-duration test exposed binary floating-point subtraction below 0.01 seconds and passed after a boundary correction.

GREEN evidence: all 45 app unit/import tests and the build pass. The six rolling browser workflows verify decoded live preview, numeric/frame/keyboard-slider edits, actual pointer release, foreign-pointer rejection, Escape/blur/pointercancel/selection/Undo/Export cancellation, autosave isolation, native download/reload and source/lock/fade/overlap rejection. Generated 1.5× left and 0.5× right footage verifies the cut moved from 1.0 to 1.4 seconds; decoded samples at 0.4/1.2/1.6 seconds are red/green/blue. Independent stereo cues decode at 0.2000625 and 1.600125 seconds (expected 0.2 and 1.6), preserving source placement; a 2-second edit decodes to 2.0135 seconds including the Opus tail. Embedded media bytes remain unchanged.

Existing regressions also pass: 16 editor browser checks, 11 Premiere import/relink checks, slip and ripple native/history/decoded-export checks, and audio playback/scratch/export checks. The audio test encodes 17,983 frames at 30000/1001 fps across ten minutes; decoded cues at 0.3000833 and 599.3000833 seconds stay within one frame. The old Premiere check expected a legacy exporter phrase; it now accepts the current precise exporter’s explicit relink-before-export diagnostic. No encoder or import behavior changed.

Run `node scripts/rolling-smoke.mjs` (or `npm run test:rolling`). Ignored `artifacts/rolling/` contains the native file, decoded-reference movie, screenshot and measured JSON results. These Edge/Windows checks do not establish arbitrary codec, hardware or NLE parity.
