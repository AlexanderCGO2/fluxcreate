# Fluximiére optimization review

Inspected: 2026-10-09. Scope: editor workflows, playback/rendering, native model, media lifecycle, import/export and AI context. Items below reflect the current code and browser checks, rather than speculative benchmark claims. Priority 0 prevents lost or misleading work; priority 1 improves core editing; priority 2 extends the editor.

| Priority | Area / issue observed | Improvement | Status and evidence |
| --- | --- | --- | --- |
| 0 | Invalid/unreadable saved data could be replaced by the starter sequence after recovery failed | Preserve original storage and pause autosave; expose original-data download and explicit Open/New recovery; block FluxLab Add with a recovery explanation | **Implemented.** 10 focused Edge recovery/race groups; ordinary media cannot clear quarantine |
| 0 | Delayed native/media imports could overwrite newer edits, and mixed good/bad batches could partially import | Stage every source before one commit; reject the whole batch on failure; invalidate pending operations on Cancel, newer imports, New and Undo; guard selected-sequence review against edits | **Implemented.** Slow project cancel/new-open and same-ID New/Undo tests, corrupt second-file batch rejection; 16 existing editor checks |
| 0 | Premiere edits could only enter through a limited V1 EDL | Parse actual compressed/plain Premiere XML object graphs and Premiere-exported legacy Final Cut XML; preserve timing, source offsets and offline references | **Implemented.** Unit fixtures plus an independently Adobe-generated PRPROJ pass; Edge imports it through the real UI |
| 0 | UI/model/render order assumed only V1, V2 and A1, losing richer imported arrangements | Support V1–V16 and A1–A16, persist empty source tracks, scroll vertically, let the inspector move clips between compatible tracks | **Implemented.** Import/track order/model rejection tests and undoable V4 browser movement; higher picture tracks paint above lower ones |
| 0 | A failed wrong-type relink was followed by a success notification | Only report successful commits; retain original path hints and references; detect a project switch while media loads | **Implemented.** Wrong-type relink leaves the original asset unchanged in Edge; native save and undo retain path hints |
| 0 | Missing picture footage could be exported as a finished-looking WebM containing offline slates | Refuse movie export until visible video/image clips are relinked | **Implemented.** Browser export shows a specific relink message; standard complete-media WebM still decodes |
| 0 | Import safety needed defined bounds and atomic rejection | Limit compressed input, decompressed XML, nesting and elements; reject entities, invalid references and unsupported track counts before committing | **Implemented.** Malformed XML, duplicate/missing object references, gzip truncation and expansion-limit tests; browser current edit remains unchanged |
| 0 | Export picture and sound consistently | Shared PCM semantics, precise WebCodecs/Opus mux, explicit real-time fallback and cancellation | **Implemented bounded increment.** See [audio test evidence and limits](AUDIO-ENGINE.md); hardware/device/proxy qualification remains |
| 1 | Source relink lengths can be shorter than imported trims; Premiere audio can reference a video file | Warn about source-duration mismatches and allow audio relink to video soundtracks | **Implemented.** Metadata is validated; original audio clip type is retained. Add visible out-of-range badges and repair actions next |
| 1 | Title/image/card left trim incorrectly depended on source-in time | Apply media bounds only to video/audio clips | **Implemented.** Edge extends an imported title before its original start without fabricating media offsets |
| 1 | Every painted clip searched the whole asset array each frame | Build one asset lookup per render | **Implemented.** Removes repeated linear searches without changing timing or drawing behavior; existing playback/export tests pass |
| 1 | Import metadata elements could retain callbacks/resources after failure | Clear metadata callbacks, source and timeout on success, codec failure and timeout | **Implemented.** Covered through image import and rejected relink browser workflows; heap profiling remains to be done |
| 1 | MediaPool retains removed clip elements for the lifetime of the preview | Prune obsolete element keys after edits and project replacement; clear error callbacks on disposal | **Next.** Measure decoder and memory counts after repeated import/delete/undo before choosing a cache policy |
| 1 | Playback sorts clips and redraws the complete canvas every frame; previews use full resolution | Cache clip ordering/asset indexes by immutable project identity, optionally paint a smaller preview and full-resolution exports | **Next.** Add 500/2,000-clip timelines and frame-time/heap measurements; avoid caching by object contents each frame |
| 1 | Whole-project undo and IndexedDB autosave copy embedded media repeatedly | Separate immutable blobs from edit metadata and use structural history sharing; package blobs on portable export | **Next.** Current history is limited to 40 states, but this is not a memory budget; preserve offline portability and undo correctness during migration |
| 1 | Real-time MediaRecorder export depends on tab visibility and cannot guarantee frame-exact output | Add deterministic frame rendering with WebCodecs where available, plus cancellation and codec fallbacks | **Next.** Keep existing real-time export until decoded-frame timing and audio sync are measured |
| 1 | Native Adobe effects, variable retiming and title graphics have no supported equivalent | Build an import review list with clip locations and explicit rendered-replacement actions; extend properties only from documented/verified samples | **Next.** Current transfer notes state unsupported content; no effect fidelity is claimed |
| 1 | AI edits are safe and undoable, but source timing proposals can exceed actual footage | Include available source ranges in the already media-free context and reject/apply warnings for out-of-range edits | **Next.** Continue excluding file paths and media bytes; test selection scope, locked clips and generation/edit plans |
| 2 | Timeline audio graphics are decorative rather than measured waveforms | Decode waveform peaks locally with cached summaries and show honest unavailable states | **Next.** Synthetic texture remains only a visual placeholder |
| 2 | Each audio/video cut is separate with no linked-selection or ripple model | Add linked groups, track targeting, snap guides and explicit ripple tools | **Next.** Requires editing invariants for source offsets, linked audio, gaps and locked tracks |
| 2 | Exchange to other suite apps simplifies animation/effects; EDL loses additional tracks | Add supported legacy Final Cut XML export for cuts/titles/media paths and extend shared motion mappings with fidelity notes | **Next.** Keep native Fluximiére project as the full editable source |
| 2 | Long sequences and many tracks are cumbersome on narrow screens | Add timeline height adjustment, keyboard track navigation, clip search and import-note jump links | **Next.** Current shared vertical scroll and track inspector are the initial improvement |

## Verification recorded

- 28 unit tests passed, including 13 timeline-import tests and 15 existing model tests. The independently produced Adobe fixture was available and ran rather than being skipped. Independent review added a regression for same-named nested sequences retaining separate relink targets.
- 11 Premiere/XML Edge checks passed: sequence choice, source trim/speed, track movement/undo, real PNG relinking/rendered pixels, retained native path hints, relink undo, wrong-type relink, offline movie export block, editable XML title, earlier title trim, atomic malformed import, autosave, and actual Adobe project import (some are grouped into one check).
- 16 existing Edge checks passed: demo, edits, trim/split, playback, image/audio/video import, AI preview/apply/undo with an injected planner, autosave and playable WebM.
- Production build succeeded. No paid model call was needed; no source media location was fetched by the importer.

Performance work still needs repeatable large-project benchmarks. This review does not claim a measured frame-rate or memory improvement beyond the specific lookup/lifecycle changes above.
