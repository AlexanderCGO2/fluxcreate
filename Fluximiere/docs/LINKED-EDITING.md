# Aligned picture and sound

Approved scope: one video and one audio clip form an explicit aligned pair. They share timeline start, duration and playback rate; their source-in offsets may differ. Linking preserves those established offsets. This is not automatic sound synchronization or J/L editing.

Native projects upgrade to version 2 when a link is first created and remain version 2 after unlinking. Each member stores the same `linkId`; validation rejects incomplete, duplicated, mistyped or misaligned pairs. The linked picture stays muted because the audio member owns sound. Unlink preserves mute, gain and geometry. Legacy version 1 remains readable. Native envelopes retain their outer version 1 and their complete version 2 project. Portable motion, EDL and Flux Exchange do not retain links; display explicit loss notices. Embedded studio source text preserves the original native file.

Separate linked sound first decodes the actual soundtrack with the existing bounded AudioStore. It copies source timing, speed, gain, mute and fades to a new audio clip, chooses the first audio track without an overlapping clip, mutes the picture and creates the pair in one transaction. Sources without a decodable soundtrack, full tracks, clip capacity, stale project/selection, import in progress and locks fail without mutation. Existing aligned pairs can be chosen explicitly; linking mutes picture sound visibly. All source checks use measured bytes, not retained asset duration metadata.

Move, start/end trim, split, duplicate and delete invoked from either member affect both atomically. Unlink also checks both locks. Frame offsets preserve imported subframe phase; numeric positions snap to the absolute sequence grid. Move, duplicate and extending end trims extend sequence duration when needed, up to the existing 86400-second limit; negative starts fail. Trims and split require at least one frame and reject any fades or transitions. Move/duplicate preserve fades. Equal rates and source-in differences remain fixed through trim/split. Gain, opacity, names, track and lock are per-member properties; speed/source edits require unlinking.

Pair gestures use separate preview state and commit once. Autosave, native/export and audio playback use the committed project. Escape, blur, pointer cancel/lost capture, playback, selection, context, import or source changes cancel. Foreign pointers cannot commit or start legacy edits from preview coordinates.

Existing slip/roll/slide reject linked participants. Ripple rejects every affected linked member, including downstream clips and all-track scope. AI temporal/split/delete/duplicate edits reject linked members. Source relinking rejects any linked use of that source. Importers report that external relationships are not reconstructed. Validator safeguards apply to every commit.

Validation: RED pure command/schema/bypass contracts before implementation; actual browser movie plus WAV fixtures with source offsets and speed, same-source extraction without doubled sound, both-member commands, locks/capacity/handles, native reopen/Undo/redo, gesture and async cancellation, committed-only export/autosave and decoded frame/tone timings. Run all app units/build and targeted editor, import, ripple, slip, rolling, slide and audio/export regressions. No shared files, dependencies or audio-engine changes.

Implemented and verified on 2026-10-15. The preceding design records the approved bounded behavior; this is a partial implementation of linked editing, not full Premiere trimming parity.

## Measured verification

- New pure contracts: 13 passing groups covering native v2 and legacy v1, pairing/cardinality, both locks, measured source bounds, frame phase, trimming/splitting, capacity, source replacement and indirect editing bypasses. The initial nine groups were RED before implementation; strict numeric-time and explicit EDL-loss cases were also observed RED before their fixes.
- All app unit tests: 65 passed. Production build passed.
- Linked browser regression: 19 passing groups using actual embedded WebM and stereo WAV sources, including controls from either member, pointer trims, cancellation, foreign pointers, held soundtrack decoding interrupted by an import before project replacement, native save/reopen, Undo/redo and fractional-rate frame movement. Source metadata deliberately says 99 seconds; measured source bytes still bound the edits. A video with no audio track is rejected; decodable silence remains valid audio. Separating a pre-muted picture keeps its new sound muted.
- Before/after separation exports decode to identical stereo RMS values (left 0.0326452053, right 0.0327037816) and identical onset times (1.0000625 and 1.6667083 seconds). Fades and volume are preserved; sound is not doubled.
- After linking separate sources with differing source-in offsets, moving, trimming and splitting at 1.5×, decoded tone onsets are 1.5000625 and 2.1667083 seconds. Green/blue sampled frames match the source positions. The three-second output decodes to 3.0135 seconds including the documented Opus tail.
- Existing browser regressions pass: editor 16 groups, Premiere import 11, ripple 1, slip 6, rolling 6, slide 12. A scoped execution of the existing audio smoke adds 6 groups for mixing, playback/reverse scratch, stereo decode, visual timing, cancellation and memory/missing-source rejection. Its unchanged ten-minute benchmark was not repeated; no audio-engine changes were made.

Evidence is generated in artifacts/linked/ by scripts/linked-editing-smoke.mjs. It includes native output, before/after/edited WebM, a usable-controls screenshot and measured JSON. Other regression artifacts remain in their existing folders. Scratch regression logs are excluded from release.

## Deliberate limits

Only one video and one audio clip may be linked, with identical timeline extent and speed. Existing source offsets express sync already established by the user; there is no waveform matching or new sync-offset editor. Unlinking keeps both clips and keeps picture sound muted. Moves, duplicates and extending end trims extend sequence duration, and sequence shortening cannot hide a linked tail. Pair trim/split reject fades or transitions; moving/duplicating preserves them. Editing speed or source, advanced trimming, AI timing commands, and replacement media require explicit unlinking. Other tracks do not ripple. Source media bytes are unchanged.

Native .fluximiere keeps inner version 2 and the shared outer envelope remains version 1. Version 2 stays after unlinking, so older editors reject it instead of silently losing links. Embedded studio source snapshots preserve the exact native file. Flux Exchange contains converted portable motion only; it does **not** carry a Fluximiére-native snapshot or links. Its export notice and notes explicitly report this loss, as does EDL. External timeline imports remain independent clips and report that original relationships were not reconstructed.
