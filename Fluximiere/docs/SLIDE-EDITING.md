# Slide editing

Scope authorized 2026-10-13: move a selected video or audio clip between exactly adjacent same-type clips on its own track. The selected clip keeps its duration, source-in, speed, gain and content; only its timeline start changes. The left neighbour extends/shortens its end; the right neighbour moves its start, changes duration oppositely, and advances its source-in by the moved timeline interval times its own speed. The left start, right end, sequence duration, media bytes and all other clips/tracks remain fixed. Picture and sound slide independently.

Reject atomically for a missing neighbour, gap, ambiguous adjacency, additional same-track overlap anywhere across the three-clip span, any lock/fade/transition, mixed untimed types, invalid rates/source ranges, unknown/unreadable/offline media, insufficient handles or less than max(one sequence frame, 0.01 seconds) in any clip. UI reads all three actual source durations; stored duration metadata is not trusted. Numeric absolute start snaps to the sequence frame grid. Whole-frame offsets preserve an imported subframe start phase and use actual fractional fps.

Interaction: inspector numeric start, earlier/later frame buttons and keyboard-accessible preview slider. Pointer movement updates program/timeline preview separately from committed project/autosave/native/movie export; release commits once. Escape, window blur, pointer cancellation, lost pointer capture, changed selection/document or another editing/modal context discard the draft. Ignore foreign pointer events. Capture belongs only to the gesture; cleanup releases it. Stale callbacks cannot commit. No-op numeric/frame actions add no history.

Validation before implementation: RED model contract and missing browser control. Then real model/source-time tests; live source preview, numeric/frame/keyboard/pointer operations, one Undo/Redo, native reopen/autosave, source locks/bounds/gaps and cancellation tests. Generate colored footage plus stereo WAV cues, export the real UI movie and independently decode picture and sound with nontrivial source offsets and speeds. Run full app units/build and existing editor, Premiere, slip, rolling, ripple and audio browser/export regressions. No linked clips, proxies, schema change, dependencies or shared-suite changes. Measured results follow only after passing checks.

## Implemented workflow and verification

Select the middle clip and use **Slide clip** in Clip properties. Enter **Selected start** and press Enter or Apply slide, use the one-frame buttons, or focus the slider and use arrow keys. Drag the slider to preview all three clips and release to apply once. Starting a slide pauses playback. Starting playback during a draft cancels it, so picture preview and committed sound cannot disagree. While a slide owns the gesture, timeline clip drags from a second pointer are blocked; other pointers cannot commit, cancel or overwrite that draft.

The three media durations are measured from embedded source bytes. Even the selected clip must have a readable valid source range although its content stays unchanged. All fades are conservatively rejected, including those on the selected clip; this slice does not reconstruct transition envelopes or link independent picture and sound. The inspector is the slide entry point; dragging a timeline clip still uses its existing move/slip tool.

RED evidence: all seven new model contracts failed before the slide command existed, and the browser workflow failed at the absent Slide start time control. Review then reproduced two further failures: Space left an active preview visible during playback, and a second pointer on a previewed timeline clip wrote the draft start into the committed project. Both received bounded guards and passing browser regressions before completion.

GREEN on 2026-10-13: all **52** app unit/import/audio-model tests, the build, **12 slide browser groups**, **16 existing editor checks**, **11 Premiere import/relink checks**, **6 rolling groups**, **6 slip groups**, and the ripple native/history/decoded-export regression pass. The slide groups exercise actual numeric/frame/keyboard/pointer controls, foreign timeline pointer rejection, one Undo/Redo, no-op history, cancellation on Escape/blur/pointercancel/lostcapture/selection/Undo/playback/export, committed autosave/native output, native reopen and fractional 30000/1001 frame offsets. Native metadata deliberately says 99 seconds; actual media reads reject invalid left, selected and right ranges and constrain extension handles.

A generated three-second movie uses 0.5× neighbours and a 1.5× selected clip with nonzero source offsets. Sliding the selected clip from 1.0 to 1.4 seconds leaves its source-in at 1.0 and duration at 1.0; the right source-in moves from 3.0 to 3.2 while its source-out stays 3.5. Actual UI export decodes stereo cues at **0.3001667, 1.7000625 and 2.6001667 seconds**, expected 0.3, 1.7 and 2.6. The middle cue moves by 0.4 seconds; neighbour cues retain their timeline positions. Decoded samples at 0.3/1.2/1.5/2.3/2.8 seconds are blue/blue/green/blue/yellow, retaining the selected clip’s green/blue content at its new location. Audio duration is **3.0135 seconds**, including the existing Opus tail. Source bytes, supported native fields and sequence duration remain unchanged.

Run `node scripts/slide-smoke.mjs` or `npm run test:slide`. Ignored `artifacts/slide/` contains the native project, movie, usable-controls screenshot and measured JSON results. These are local Windows/Edge checks, not arbitrary codec/hardware qualification. The audio engine/exporter were unchanged; the earlier ten-minute benchmark was not repeated in this slice.
